# AHB

**面向连锁品牌总部内容运营团队的 AI 视频工作台。**

AHB 希望把门店拍到的真实素材，变成总部能选择、修改、审核，并用于矩阵账号的视频。工作台围绕“今天发什么、手里有什么、怎么剪、选哪版、发布后如何”组织工作，让运营人员把时间用在内容判断上。

当前是可运行的本机验证版本。素材分析、候选剪辑、逐段修改、成片回放与发布表现关联已接通；门店远程上传、团队权限、正式审核和矩阵自动分发尚未实现。本文及[产品设计文档](docs/design.md)的状态截至 **2026-10-22**。

新协作者先读本文，再读[协作与本机开发](CONTRIBUTING.md)和[产品设计](docs/design.md)。历史讨论的适用范围见[文档口径](CONTRIBUTING.md#文档口径)，不按旧调研或聊天中的待审提案直接扩展功能。

## 为谁做

第一批聚焦有实体门店、持续内容需求和矩阵账号的品牌，例如餐饮品牌、网球场馆。优先使用者是**总部内容运营**。

| 角色 | 要完成的事 | 在产品中的位置 |
|---|---|---|
| 总部内容运营、编导、剪辑 | 找选题、挑素材、比较剪法、修改成片 | 首要使用者，当前先验证其制作工作 |
| 门店员工、店长 | 拍摄并交回真实的菜品、服务、人物与门店画面 | 素材提供者；独立门店上传入口待建设 |
| 品牌内容负责人 | 判断是否符合品牌表达、事实与活动要求 | 目标审核角色；当前需人工线下审核 |
| 总部或受托运营团队 | 将确定版本发布到相应账号，再复盘 | 目标分发角色；当前导出后人工发布 |

预期采购方是品牌方的内容或营销负责人，但预算、采购方式和定价还需要客户试点验证。结合食亨代运营开展交付是已选方向，具体由谁拍摄、制作、审核、发布及收费，尚未确定。

## 产品意图

项目起点是复用星尚工作流经验，做通用 AI 剪辑。随着场景明确，优先级收敛到**总部集中制作，门店提供素材**：

- 从年度活动、月周计划和近期平台线索，形成当天值得做的内容。
- 从门店实拍中找到可用动作、原声和内容，减少反复翻素材。
- 给总部提供有实质差异的可播放方案，保留人的最后选择。
- 把剪辑处理做成可检查的节点，能看原片取用区间、处理后片段和保存的决策。
- 留下选择、修改、成片版本与发布表现的对应关系，为之后的改进积累依据。

现阶段先验证“能否做出总部愿意采用的片子，以及是否减少人工处理时间”。不以生成数量、模板数量或预测爆款作为成功标准，也不开始训练评分模型。

## 一条目标工作流

**运营计划 → 门店素材 → 总部选材与制作 → 候选比较与修改 → 总部审核 → 矩阵发布 → 表现复盘**

例如，以「隆莱呷卤肉饭」作为示例品牌：总部围绕午餐场景形成选题，选用门店拍摄的浇卤、装盘、取餐画面，生成不同节奏的版本；运营人员对照节点改片，负责人核对后，再交由发布人员发布到适用账号。店址、活动、价格和门店适用范围应来自品牌确认，不能由 AI 补造。

这个例子描述产品方向，不代表隆莱呷已成为客户，也不代表示例运营计划是品牌官方计划。当前门店交片、审核和发布仍在工作台之外完成。

## 当前能做什么

| 工作面 | 已有能力 | 当前边界 |
|---|---|---|
| 运营首页 | 年度节点、周/月计划、今日选题、公开抖音线索；选题可改期并带入制作 | 以隆莱呷为示例；线索来自公开综合榜筛选，不是垂类全量热榜 |
| 素材&分析 | 上传图片、视频和音频；自动排队分析、本机转写；日期日历、缩略图、标签、内容与片段选择 | 本机素材库，尚无门店归属与跨店权限隔离 |
| 开始剪辑 | 可操作节点、素材替换与排序；自然语言修改单镜头的选材、区间/展示时长、字幕和切入；每批 3–5 条实际预览供人选择 | 单节点自然语言变速、改声音尚未接通；不替人选定或发布，素材不足时不用重复视频凑数 |
| 菜品食欲片 | 动作复核、选段、恒定变速、原声与配乐分层、部分音乐起音对齐 | 已验证单条烹饪链路；该模板的多候选质量尚未专项验收 |
| 剪辑拆解 | 按成片版本查看原片片段、剪后片段、DS 保存的决策与实际参数 | 展示留存记录，不在查看时补写解释，不代表模型隐藏推理 |
| 样片分析 | 分离检测镜头、语义内容段与声音节奏；按叙事、运动衔接等方式展示 | 识别仍可能出错；样片与可用素材分开管理 |
| 素材生成 | MiniMax H3 分镜生成、单段修改重生成和顺序拼接；DS 编写 HTML 动画后本机导出视频 | 辅助补充画面；H3 需确认费用，动画有独立运行依赖 |
| 工作空间 | 按业务项目查看本机作品、版本、播放和下载 | 剪辑作品只读浏览，不是团队协作或审批系统 |
| 历史数据分析 | 按项目、平台查看已导入数据；人工绑定确切成片与发布记录 | 目前接入星尚已有采集；不自动发布、不训练模型、不做跨平台总分 |

## 先不做什么

暂不扩展独立门店任务单、完整专业非线性编辑器、无人审核的批量发布、爆款预测和自动模型训练。账号、订阅、团队权限和支付属于产品化阶段，当前没有这些能力。

保留样片学习、H3 和网页动画能力，但近期开发优先服务门店实拍的选材、剪辑与人工审片。详细取舍、角色边界和验证方法见[设计文档](docs/design.md)。

## 本机运行

当前主要在 macOS、Python 3.12 环境验证。需要可用的 `ffmpeg`、`ffprobe`；字幕渲染需要带 libass 的 FFmpeg 和中文字体。依赖中包含 `imageio-ffmpeg`，渲染器会检查可用的字幕支持。

```sh
git clone https://github.com/nsc328-del/AHB.git
cd AHB
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

打开 [http://127.0.0.1:8787](http://127.0.0.1:8787)。已有本机环境可双击 `start.command`。关闭服务不会删除素材与作品。

DeepSeek 和 MiniMax 由后端读取 `DEEPSEEK_API_KEY`、`MINIMAX_API_KEY` 环境变量，或本机私密配置 `~/.config/video-ai-studio/providers.json`；私密配置优先于环境变量，项目 `.env` 不会自动加载。页面没有密钥输入界面。H3 仅在需要生成视频时使用；普通剪辑不调用 H3。语音转写首次运行需要下载公开模型权重。配置优先级、旧星尚配置复用和独立开发数据目录见[协作说明](CONTRIBUTING.md#本机开发)。

服务默认会汇总已满足条件的历史素材日，启动时也会检查，可能产生 DeepSeek 调用。只调界面或做离线检查时，用 `VIDEO_STUDIO_DAILY_SUMMARY=0 .venv/bin/python app.py` 关闭这项后台汇总；该开关不关闭上传后的自动分析或其他主动 AI 操作。

HTML 动画导出另外需要已安装的 Google Chrome，由 Playwright 在独立临时环境中逐帧渲染，结束后关闭。它是代码渲染，不会操作剪映或用户的浏览器窗口。

仓库不包含 `data/`、`output/`、`.venv/` 或密钥。新克隆不会带出本机试片、历史采集和已有作品；默认数据存入项目 `data/`，可用 `VIDEO_STUDIO_DATA` 指定独立目录。星尚历史同步还依赖维护者的只读数据源连接，新协作者不默认拥有该连接。目前只监听本机回环地址，不能当作已完成账号隔离的企业在线服务部署。

## 模型、数据与费用

- **DeepSeek**：观察证据帧、理解内容、组织方案、修改镜头和编写提示词。
- **Python / FFmpeg**：抽帧、媒体检测、时间线校验、变速、声音混合与成片导出。
- **MiniMax H3**：经确认后生成新视频素材；官方 Skill 快照与适配记录位于 [vendor/skills](vendor/skills/README.md)。

原件和工作记录保存在本机，模型请求会发送该任务所需的描述、证据帧或参考素材；“本地保存”不等于完全离线。品牌资料与素材需在获准范围内使用。现有历史发布文案和表现数据不发送给模型，也不进入候选排序。

用量胶囊记录供应商实际返回的 Token、缓存字段或视频秒数。缺失值不估算；本地阶段结果复用与供应商缓存命中分别记录。H3 未知提交只查询原任务，不自动重发收费请求。

## 验证与已知限制

已用 148.8 秒公开连续烹饪记录做出 23.43 秒蛋包饭试片：7 段、无字幕，包含动作取舍、变速、原声/配乐分层和两处音乐起音对齐。成片及原片/剪后片段可在本机「工作空间 → 餐饮实测」查看。

这证明了一条可执行链路，尚不证明门店素材上的普遍质量或业务收益。DS 仍可能误判动作与运镜，ASR 可能错字；当前声音节奏依据本机测量，DS 没有直接听音，未实现具体煎炒声或器具声识别。该次开发联调 13 份回执共 353,185 Token，含失败与重试，不能作为成熟产品的单片成本。

本机验证记录位于 `output/appetite-pilot-20261021/` 等目录，不随仓库分发。历史实现记录可从 Git 提交查看。对后续试点的验收口径见[设计文档：验证收益](docs/design.md#验证收益)。

```sh
VIDEO_STUDIO_DAILY_SUMMARY=0 .venv/bin/python -m unittest discover -s tests -p 'test_action_editing.py' -q
node --check static/app.js
```

按改动选择渲染、回放或接口检查，命令与验证边界见[协作说明：提交与验证](CONTRIBUTING.md#提交与验证)。上述检查不调用真实模型，也不证明模型内容质量。
